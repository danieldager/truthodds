Tier-1 Verdict Cache

System overview & calibration results — 2026-06-05

The cache stores every claim we confidently fact-check (text + embedding + verdict + sources), and reuses a stored verdict for a future claim only when a logical-equivalence check confirms they are the same claim. It also grows into a record of which claims circulate and how often (a misinformation observatory). Storage: Postgres + pgvector.

How a claim flows through the cache

  1. Normalize the incoming claim to a canonical, attribution-stripped form.
  2. Embed it (384-d multilingual MiniLM, L2-normalized).
  3. Retrieve candidates (stage 1, cosine ANN): nearest stored claims with cosine ≥ 0.60. This is only a recall filter — it decides what is worth checking, not what to reuse.
  4. Equivalence gate (stage 2, the safety arbiter): a bidirectional LLM judge compares the new claim against each candidate cluster's canonical claim and its nearest member. It must confirm the same fact-check verdict applies to both.
  5. Hit → reuse the cached verdict (subject to a freshness window) and fold the claim into that cluster (update its centroid + member count). Miss → fall through to full verification, then store the new verdict as a new cluster.

Key principle: cosine is the recall filter; the gate is the precision arbiter. The adversarial cases that flip a verdict (negation, number/entity/scope swaps) sit close in embedding space, so cosine alone cannot separate them — the gate must.

Test setup (calibration run, 2026-06-05)

  • Seed cache: 66 AVeriTeC claims we had verified correctly (verdict = gold label; 52 Refuted, 14 Supported).
  • 500 generated variants of those seeds — 264 that should match (paraphrase / synonym / reorder / filler) and 236 that must not (negation / number / entity / scope swaps).
  • Gate: llama-3.3-70b, bidirectional. Each variant matched against its source claim.
  • Adversarial variants sit close in embedding space: mean cosine 0.868 vs 0.926 for true paraphrases (negations land at ~0.92).

Cosine alone is unsafe — precision ~0.53, false-hitting up to 99% of verdict-flipping variants. Adding the gate holds precision at ~0.98 across every threshold. Because precision is bounded by the gate (not the cut), the cosine threshold is set low (0.60) to keep recall ~0.87; raising it only discards true matches.
